# AE 插件管理器 / AE Plugin Manager

> [English documentation](README.en.md) · 中文

> 仓库：https://github.com/DcC176/ae-plugin-manager ｜ 下载：https://github.com/DcC176/ae-plugin-manager/releases/latest

一个轻量的 After Effects 插件管理工具：**扫描纳管已有插件、检测冲突与不适用的插件、拖入压缩包一键安装**，思路参考 Blender 的 BLT。
单文件 exe（**约 163 KB**），Windows 10/11 自带 .NET Framework 运行时即可运行，无需安装任何依赖。**界面支持中英文**（菜单「界面语言」切换，启动时也会自动跟随系统语言）。

```
dist\AEPluginManager.exe     ← 直接双击运行（发布用的英文名）
```

> 中英文共用同一个 exe：语言是运行期选项，菜单「界面语言」里切换，或用 `AEPluginManager.exe --lang en` 启动。

## 一、安全设计（最重要的一节）

软件会写入 AE 的插件目录，因此对"不可逆损害"做了硬性约束：

| 约束 | 实现方式 |
|---|---|
| **AE 目录内没有"删除"操作** | "卸载"= 把文件**移动到回收区**，可一键还原；软件里不存在真删除 AE 文件的路径 |
| **覆盖前必先备份** | 每次覆盖都把原文件复制到数据目录 `backup\<会话ID>\old\`，装坏了可以还原 |
| **失败自动整体回滚** | 安装过程中任一步写入失败（文件被占用、权限不足），本次已写入的改动全部撤销，AE 目录回到操作前状态 |
| **只写 AE 安装目录** | 所有目标路径必须落在已发现的 AE 安装目录/共享插件目录内，越界写入被拒绝并记日志 |
| **唯一真删的是备份区** | 「彻底删除备份」只删除 `E:\AE插件管理器\` 里本软件自己的备份，永不触碰 AE 目录 |
| **不代为执行安装器** | 插件自带的 `.exe/.msi` 安装器不会静默运行，只提示你手动安装（避免注册表/系统目录被写入） |

数据目录默认 `E:\AE插件管理器\`（与 AE 同盘，跟随 AE 所在盘符），内含：

```
E:\AE插件管理器\
  ├─ backup\I20260930-114422\   安装时的原文件备份 与 "本次新增文件" 清单
  ├─ recycle\U20260930-114613\  卸载移入的文件（可还原）
  ├─ sessions.tsv               操作记录（界面「回收区」读取它）
  └─ log.txt                    每次写入的详细日志
```
菜单「软件 → 更改备份位置」可改到别处。

## 二、功能

### 1. 已安装插件（纳管）
- 扫描 3 个 AE 版本（2020 / 2024 / 2025）的 `Plug-ins`、`Scripts`、`Presets`。
- 支持按 AE 版本、按类型筛选；列表显示名称、类型、位数、大小、相对路径、修改时间。
- 双击条目在资源管理器中定位；选中「卸载到回收区」即移入回收区。
- 自动识别 `.aex`（特效）、`.jsx/.jsxbin`（脚本）、`.ffx`（预设）、`*.plugin`（编解码包）、CEP 扩展。
- Adobe 自带脚本（`Scale Composition.jsx` 等）不计入第三方插件，避免噪音。

### 2. 冲突与不适用（检测 + 一键修复）
> 只在**同一个 AE 版本内**出现多版本插件冲突时才提醒。不同 AE 版本各装一份是正常用法，不做提醒。

| 规则 | 级别 | 一键修复 | 说明 |
|---|---|---|---|
| 放错目录 | 严重 | ✅ 移入回收区 | `.aex/.8bf` 放在 `Scripts` 下——AE 只从 `Plug-ins` 加载，这类文件不会被加载，还可能与 `Plug-ins` 里的同名副本打架。实测命中你机器上 AE 2024/2025 的 `Scripts\RealGlow.aex`。**仅当 `Plug-ins` 下已有同名副本时才提供一键修复**；否则只给指引，避免把插件删到彻底不可用。 |
| 同版本重复 | 严重 | ✅ **由你选保留哪一份** | 同一个 AE 版本里同名插件有多份（例如 `Plug-ins\RealGlow.aex` 与 `Plug-ins\Trapcode\RealGlow.aex`）。AE 只会加载其中一个，加载哪个取决于目录扫描顺序。点「选择保留哪一份…」会弹出列表，逐个显示**大小 / 版本位数 / 完整路径 / 修改时间**，你勾一份保留，其余移入回收区。软件不替你决定哪份是你想要的。 |
| 位数不匹配 | 严重 | ✅ 移入回收区 | 32 位/ARM 插件在 64 位 AE 上会被静默忽略（读 PE 头判定，不靠文件名猜） |
| AE 正在运行 | 注意 | 查看关闭方法 | 提示先关闭 AE，否则插件文件被占用会导致写入失败（不强制结束你的进程） |
| 安装残留 | 提示 | ✅ 移入回收区 | `.bak/.old/.tmp` 与 mac 的 `._*` 资源分支文件 |
| 孤立资源目录 | 记录 | — | `<插件名>_ffx` 这类资源目录在插件被移除后残留 |

点选任一问题，下方会直接给出**【修复方案】**说明「会动哪些文件、动完什么结果」，点「一键修复」即执行——
所有修复动作都是**移动到回收区**，不真删，随时能在「回收区」还原。工具条右侧会统计"可一键修复 N 项"。

### 3. 安装插件（拖入 → 选版本 → 一键安装）
把 **`.zip` / `.rar` / `.7z` 压缩包、解压后的文件夹、单个 `.aex/.jsx/.jsxbin/.ffx` 文件**拖进窗口，软件会：

1. **只解压需要的文件**：自动跳过教程视频、图片、网址快捷方式、广告目录等。实测 `AutoSway` 包 85 MB，只为装 4.4 MB 的插件而跳过 80 MB 视频。
2. **列出可安装的内容让用户自己选**：包里有中文版/英文版/Mac 版，或既有主脚本又有独立预设目录时，中间会出现候选列表（默认勾选推荐项，标 ★），例如：
   ```
   ★ 根目录（含全部内容） · 3 个文件 · 4.4 MB
     AutoSway_ffx · 2 个文件 · 30 KB
   ```
   切换选项下方方案实时重算——**不会替你默默决定装哪个**。
3. **自动定位载荷根目录**：吸收 `Deep Glow v1.5.5\` 这类单层壳目录，按你现有插件目录的习惯直接落盘到 `Plug-ins\Deep Glow.aex`。
4. **带上依赖目录**：脚本类插件的 `AutoSway_ffx\` 会跟随脚本装到 `Scripts\ScriptUI Panels\`。
5. **按类型映射目标**：`.aex/.dll → Plug-ins`、`.jsx/.jsxbin → Scripts\ScriptUI Panels`、`.ffx → Presets`、`.plugin → (Media Core plug-ins)`。
6. **先给方案再落盘**：列出"哪个文件 → 写到哪个目录 → 是否覆盖现有文件"，勾选要装到哪些 AE 版本，确认后才执行，执行前自动备份。
7. **中文文件名兼容**：国内大量插件包用 GBK 存文件名却不设 UTF-8 标志，软件会自动按系统码页正确解码（否则解压出来是一堆乱码目录）。
8. **只有安装器的包也能装**：包内没有可直接复制的插件文件、只有 `.exe/.msi` 安装器时（例如 HeatDistortion），软件会把包内所有安装器列出来并**推荐**一个（本机架构 + 中文版优先，带 `fix` 后缀的降权），你确认后由软件**拉起安装向导**：
   - 不静默、不加任何隐藏参数、不替你点下一步；
   - 装完后软件**自动重新扫描** AE 目录，直接告诉你这次新增/更新了哪些插件；
   - 若安装器需要管理员权限（常见于装到 `C:\Program Files\Adobe\Common\Plug-ins`），另有一个「以管理员身份运行安装器」按钮。

   实测（用自制安装器验证链路）：包内只有安装器 → 列表出现安装器 → 运行 → 载荷写入 AE 目录 → 自动重扫报出「安装完成，本次新增/更新了 1 个插件：AE 2024　__TEST_FAKE.aex」。

### 4. 回收区（回滚）
- 每次卸载/覆盖都形成一条会话记录，显示操作类型、时间、内容、文件数。
- 「一键还原」把文件放回原位置（安装会话则还原被覆盖的原文件）。
- 「彻底删除备份」只删备份区数据。

## 四、构建与自检

### 构建
```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```
用系统自带 `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe` 编译，产物 `dist\AEPluginManager.exe`（约 121 KB，零依赖）。加 `-Lang zh` 可让产物用中文名。GitHub 上另有 `.github/workflows/build.yml`，在 windows-latest 上跑同一条 csc 命令校验源码可编译。

### 命令行自检（全部只读或显式指定动作，便于排错与脚本化）
```powershell
# 列出发现的 AE 安装与共享插件目录
AE插件管理器.exe --list

# 只做识别，输出安装方案（不写任何文件）
AE插件管理器.exe --detect "D:\xxx\Deep Glow v1.5.5 Win.zip" --version 2024

# 冲突检测报告
AE插件管理器.exe --conflicts

# 安装 / 卸载到回收区 / 查看会话 / 还原（与界面共用同一套执行与备份逻辑）
AE插件管理器.exe --install "<包路径>" --version 2024
AE插件管理器.exe --uninstall "<AE目录内的文件或目录>"
AE插件管理器.exe --sessions
AE插件管理器.exe --restore <会话ID>

# 界面自检：把 4 个标签页离屏渲染成 PNG（不抢鼠标键盘焦点）
AE插件管理器.exe --shot "<输出目录>" [--detect "<包路径>"] [--detect2 "<另一个包>"] [--choice <候选序号>]
```
报告写在 `%TEMP%\AEPluginManager-report.txt`（UTF-8，避免控制台编码问题）。

## 五、源码结构

```
src\
  Model.cs      数据模型：插件分类、AE 实例、已安装条目、冲突（含修复方案）、版本候选、安装方案
  AeEnv.cs      AE 环境探测（E:\Adobe、C:\Program Files\Adobe、注册表 InstallPath）
  Scanner.cs    只读扫描器（只读，不修改任何文件）
  Conflicts.cs  冲突检测规则、修复方案生成与文本报告
  Archive.cs    解压：zip 原生（支持 GBK 文件名还原）；rar/7z 走系统 bsdtar / 7-Zip / WinRAR
  Installer.cs  安装规划：识别（解压+分类+候选列表）与方案生成（载荷根、依赖目录、路径映射）
  Executor.cs   写入执行：备份、失败回滚、卸载到回收区、还原、会话清单、安全阀
  Fs.cs         文件系统助手（建目录、复制文件/目录、目录大小、读 PE 头判位数）
  L.cs          本地化运行时：按语言查表翻译；偏好存 %APPDATA%\AEPluginManager\lang.txt
  Strings.cs    英文词条表（由 tools\build-strings.ps1 生成，勿手改）
  Ui.cs         界面基础组件与字体回退
  MainForm.cs   主窗口（4 个标签页 + 拖放 + 候选选择 + 一键修复 + 语言切换）
  Program.cs    入口与命令行自检
build.ps1       编译脚本（csc.exe；-Lang zh|en 决定产物文件名）
app.ico         程序图标
```

`tools\` 里的辅助脚本：

| 脚本 | 用途 |
|---|---|
| `make-icon.ps1` | 生成 `app.ico` |
| `extract-strings.ps1` | 从源码提取含中文的字符串字面量，生成待翻译清单 |
| `wrap-lt.ps1` | 把中文字面量包成 `L.T("...")`（字符级扫描 + 去包裹回验，防止误改源码） |
| `collect-lt.ps1` | 从已包裹的源码收集待翻译文案并按文件分组 |
| `build-strings.ps1` | 把行对行译文组装成 `src\Strings.cs`（校验行数与占位符） |
| `publish-github.ps1` | 无 git 环境下用 GitHub Git Data API 建仓库并产生提交历史 |
| `capture.ps1` / `capture-tabs.ps1` | 抓窗口截图（仅排错用，会把窗口切到前台） |

> 注：`tools\capture*.ps1` 会把窗口切到前台，仅在排错时使用；日常界面核验用上面的 `--shot`（离屏，不动桌面）。

## 七、已知边界（不做的事）

1. **安装器以向导方式运行，不做静默安装**——软件会拉起 `.exe/.msi` 安装向导并把控制权交给你；不添加 `/S`、`/VERYSILENT` 之类的参数，也不替你点下一步。这样不会有"静默写注册表/系统目录"的失控风险，代价是需要你在向导里点几下。
2. **加密压缩包不处理**——检测到需要密码就提示手动解压后拖入，不尝试询问或破解。
3. **`C:\Program Files\Adobe\Common\Plug-ins` 需要管理员权限**——默认以当前用户权限运行；若安装器写该目录失败，用「以管理员身份运行安装器」（会弹 UAC）。
4. **不解析 `.aex` 的 SDK 版本号**——只做 PE 位数校验（32/64 位）；"某插件是否支持某个 AE 大版本"需要插件自带元数据，无法可靠推断，避免猜测性报错。
5. **AE 运行中允许强制操作**——会二次确认并可能写入失败，失败即整体回滚。
6. **不跨 AE 版本判断插件新旧**——同名插件装在不同 AE 版本里属于正常用法，不提醒、不清理（这是按你的要求专门去掉的规则）。
7. **安装器如果装在别处，软件只能如实报告"没发现新文件"**——它会提示三种常见原因（取消安装 / 装到了共享插件目录 / 权限被拒），不会假装成功。
